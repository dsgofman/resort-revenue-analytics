# Overview — dbt-resort-analytics (Resort Revenue Analytics)

## What it is
A portfolio project with two halves, README.md has the full pitch:

1. A production-shaped **dbt warehouse** modeling a fictional vacation-resort company
   ("the Cabana Collection") — raw synthetic CSVs → staging → intermediate → marts,
   headlined by a finance-grade booked-vs-recognized **revenue reconciliation** model
   that surfaces a $2.64M / 12.08% variance and ties to the cent via a singular test.
2. An **AI analyst app** (`ai_analyst/`, Streamlit) on top of that warehouse:
   plain-English question → Claude Code (headless `claude -p`, no API key) drafts SQL →
   a deterministic **verification gate** (`guardrails.py`) allows or blocks it → DuckDB
   (opened read-only) executes → table + chart.

## Why it exists
A demonstration piece for David's BI/analytics background: governed data (tested,
documented dbt models) paired with governed AI (a hard gate between an LLM's SQL draft
and anything touching the warehouse) — "verify before you trust AI output," applied to
both halves of the stack.

## Goal
Portfolio/demo quality: `dbt build` green end to end, the AI analyst gate fully
unit-tested, model docs + lineage hosted publicly, README doubling as the pitch deck.
Not a production system — no real data, no live users.
